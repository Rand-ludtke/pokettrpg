## Root cause
`tauri-app/public/data/ss2-patch/generated/moves.custom.ss2-soulstones.json` (1306 moves,
PBS export) carries ONLY display fields: name/type/basePower/category/accuracy/pp/target/
priority/flags:{}/num:0/desc/shortDesc. **Zero mechanics fields** (no boosts/status/heal/
drain/multihit/recoil/secondary/weather/...). Every same-key collision with a canonical
Showdown move is dropped (Rule A) and keeps pristine canonical mechanics → those work.
Every BRAND-NEW SS2 move currently executes as either raw damage (attacking) or a no-op
(status) — e.g. Macabre Dance claims Sp. Atk/Speed boosts but raises nothing.

## Architecture (what's battle-truth where)
- Backend battles: `pokemonttrpg-backend/dist/sync-ps-engine.js` + `dist/data/moves.js`
  (generated by `pokemonttrpg-backend/scripts/generate-dist-moves.mjs`).
- Code-handler moves (protect-style, counters, custom conditions) can't live in JSON →
  they go in `customMoveEffectPatches` inside sync-ps-engine.js.
- Client never simulates battles; client JSON is display-only (already correct). Do NOT
  need to mirror mechanics fields into the client pack.
- Canonical Showdown moves come pristine from pokemon-showdown — assume correct, smoke-test
  only (execute + no crash), don't re-verify Nintendo mechanics.

## Decisions / conventions
- Desc is the spec. "Raises X by N stages" → boosts; no stage number → +1; "sharply" → +2;
  "drastically" → +3. Dance-style two-stat buffs → +1 each (Dragon/Quiver Dance convention).
- Chance-based secondaries verified by temporarily forcing chance=100 in the harness Dex
  (verification-only override), so the assertion is deterministic.
- Ambiguous/no-pattern descs get EXPLICIT overrides in `scripts/move-intent.mjs`; anything
  still unresolvable is listed in `move-audit-results.json` as `manual` and flagged here.
- Canonical moves are NOT re-verified for game-accuracy; they are smoke-tested (execute,
  no crash) since they come pristine from pokemon-showdown.
